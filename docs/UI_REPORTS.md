# Досье компании через интерфейс

Откройте http://localhost:3080, войдите существующей учётной записью и создайте
**новый чат**. Основной пресет — **DeepSeek · OSINT Авто**. В строке ввода должен
быть выбран **OSINT Orchestrator**. В старом чате мог сохраниться прежний
endpoint; после обновления используйте новый чат и актуальный пресет.

Пример запроса:

> Собери подробное досье по компании Microsoft Corporation, США, тикер MSFT,
> CIK 0000789019, официальный сайт microsoft.com. Нужны юридическая идентификация,
> корпоративная структура и руководство, годовые финансовые показатели,
> проекты и география, инфраструктура домена, источники и ограничения.
> Сохрани полный отчёт HTML, Markdown и PDF.

Для другой компании замените название, страну, сайт и известный регистрационный
номер. Указывайте только известные реквизиты: выдумывать ИНН/CIK не нужно.
Дождитесь завершения `investigate`, затем откройте HTML из ответа чата.
Полное досье находится в файле; сообщение чата содержит краткую сводку.

## Настройки качества

- Пресет чата: `deepseek-flash`; выбор внутренних источников и писатель:
  `ORCHESTRATOR_MODEL=deepseek-flash`, `ORCHESTRATOR_REPORT_MODEL=deepseek-flash`.
- Используется тот же `investigate` и тот же код досье, что и в проверенных
  отчётах. Для UI нет отдельной сокращённой сборки.
- Таймаут MCP для полного досье — 15 минут. Остальные инструменты сохраняют
  прежний лимит 5 минут. Это верхний предел ожидания, а не обещанное время ответа.
- Заголовок чата также создаёт DeepSeek: ключ OpenAI для этого не требуется.
- Явно обозначенный CIK США не трактуется как российский ИНН. Поздние ответы
  реестров дополняют идентификацию и запускают недостающие финансовые запросы,
  если это та же сущность без конфликта юрисдикции и идентификаторов.
- Из индекса годовых отчётов читается один самый новый найденный HTML-документ
  на официальном домене. При извлечении фактов модель распределяет внимание
  между страницами и не перечисляет каждый год публикации отдельным фактом.
- Имя cloud endpoint — `Cloud (LiteLLM)`. Символ `/` в старом названии приводил
  к HTTP 404 на отправке сообщения.

Полнота зависит от доступности источников и публичности данных компании.
Одинаковый конвейер не гарантирует одинаковое число фактов в каждом прогоне.
Проверяйте разделы «Источники и покрытие» и «Ограничения данных»; ответ API
с ошибкой не означает отсутствия сведений. Сбор не заменяет ручную проверку
утверждений модели и не доказывает, что собраны все возможные данные.

## Доступ с другого компьютера

`localhost` относится к компьютеру, где открыт браузер. Можно пробросить оба порта:

```bash
ssh -L 3080:localhost:3080 -L 8899:localhost:8899 USER@SERVER
```

После этого локальные ссылки UI и отчётов работают в браузере. Если UI открыт
через адрес сервера или reverse proxy, задайте в `.env` публичный URL именно
сервиса отчётов, например `REPORTS_URL_BASE=https://reports.example.org`,
и пересоздайте orchestrator. Сам DNS, TLS и reverse proxy эта переменная не настраивает.
Изменение URL применяется к новым отчётам.

## Повторная проверка

```bash
python3 generator/generate.py
python3 tests/unit_ui_config.py
```

`tests/browser_company.cjs` входит через настоящий браузер, отправляет запрос и
проверяет доступность HTML/Markdown/PDF, включая заголовки скачивания.
Он делает платные LLM-запросы и обращается к внешним OSINT-источникам.
Для запуска установите Playwright и Chromium; укажите `NODE_PATH` и
`PLAYWRIGHT_BROWSERS_PATH`, если они установлены вне проекта.
Передайте путь к защищённому JSON-файлу с `email` и `password` через
`OSINT_UI_CREDENTIALS`; не добавляйте этот файл в Git. Артефакты без пароля
сохраняются в игнорируемый `scratchpad/ui-e2e`. Флаг `--login-only` проверяет
только вход и основной пресет, без генерации отчёта.

Существующая учётная запись `admin@osint.local` и её пароль не изменялись.
Для проверки использована отдельная учётная запись с ролью USER.

## Состояние проверки на 18 сентября 2026

Вход отдельного пользователя и генерация Microsoft через UI были выполнены.
После исправления CIK/ИНН один полный прогон занял около 6 минут 21 секунды:
HTML/Markdown/PDF и все ссылки скачивания доступны, 24 нумерованные таблицы,
5 годовых финансовых периодов; отображаемые суммы совпали с прежним аудитом.
Две диаграммы, переключение темы и масштаб проверены в браузере.

После добавления перехода из индекса к годовому отчёту офлайн-тесты прошли,
но следующий полный UI-прогон завершился по 15-минутному таймауту. Причина
этого зависания не установлена; считать последнюю конфигурацию безусловно
проверенной во всех сетевых сценариях нельзя. Проверки выше относятся к
конкретным прогонам, а не к гарантии постоянной доступности внешних API.
Локальная GPU-модель в этих прогонах не использовалась.
