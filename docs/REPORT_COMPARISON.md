# Сравнение корпоративного досье с референсом

Для INDRA сохранены исходный и исправленный прогоны в
`reports/indra-comparison/`. `comparison.md` описывает тематическое покрытие и
измеримые различия; `metrics.json` содержит метрики. Каждый прогон сохраняет
`evidence.json`, краткий ответ чата и отчёты HTML/Markdown/PDF.

Референс задаёт глубину и виды данных, но не является источником фактов для
генератора. Текущий DNS, состав совета, финансовые периоды и сроки сертификатов
могут отличаться от исторического референса. Число таблиц и совпадение IP не
являются оценкой достоверности.

## Повторить прогон

Сначала собрать и запустить изменённые сервисы обычным способом. Прогон использует
конфигурацию и API-ключи работающего orchestrator; обычные лимиты провайдеров
продолжают действовать.

```bash
docker cp tests/. osint_proj-orchestrator-1:/app/tests
docker exec -e PYTHONPATH=/app osint_proj-orchestrator-1 \
  python -u /app/tests/indra_pipeline.py new-run
python3 tests/compare_indra.py --final new-run
```

Базовый прогон должен находиться в `reports/indra-comparison/baseline/`.
Перед синтезом сохраняется контрольная копия ответов: ошибка форматирования
не требует повторять сбор. Повторная сборка сохранённого материала не опрашивает
OSINT-источники, но повторяет LLM-синтез:

```bash
docker exec -e PYTHONPATH=/app osint_proj-orchestrator-1 \
  python -u /app/tests/indra_pipeline.py replay \
  --replay /reports/indra-comparison/new-run/evidence.json
```

## Изменения сбора и отчётности

- `corporate_website` следует редиректу официального сайта и обнаруживает
  корпоративные страницы по навигации и поиску в подтверждённом домене.
  Состав органов управления извлекается из HTML. Для переведённых фактов LLM
  обязан вернуть цитату и URL; цитаты и числа проверяются по прочитанному тексту.
- `borme_publications` находит официальные бюллетени BOE, отбирает записи по
  точному юридическому имени и сохраняет назначения/отзывы как исторические
  события. Это ограниченная выборка, не полный реестр действующих доверенностей.
- Поздний успешный ответ реестра позволяет повторно разрешить идентичность и
  добавить источники нужной юрисдикции. Отклонённая разведочная GLEIF-карточка
  не возвращается в утверждённые сведения через запасной вариант.
- Парсер Subfinder поддерживает вложенный `data.subdomains`. Censys использует
  запрос по DNS хостов, исключающий сертификатные записи без IP.
- `resolve_hosts` собирает A/AAAA пакетно и отдельно сообщает пустые ответы и
  ошибки. Поддоменные IP участвуют в последующем обогащении сетями и странами.
- Вызовы VirusTotal в одном процессе оркестратора выполняются последовательно
  с увеличенным таймаутом. Это не глобальный лимитер между пользователями.
- Таблицы принимают числовые значения. Лимиты выборки BORME раскрываются.

## Регрессии

`unit_entity.py`, `unit_render.py` и `unit_pipeline.py` выполняются в контейнере
оркестратора с `PYTHONPATH=/app`; `unit_corporate.py` — в directapi. Сети эти
тесты не требуют. Новые проверки покрывают потерю вложенных поддоменов,
повторное добавление неверного юрлица, числовые поля, цитаты/числа из LLM,
корпоративные роли и разделение назначений/отзывов BORME.

## Итоговый прогон INDRA

`verified/` — итоговая сборка. `baseline/` — исходный сетевой прогон;
`revised/` — сетевой прогон после основных исправлений; `final/` — повторные
запросы к неполным источникам. Имена каталогов промежуточных прогонов не означают,
что они предпочтительнее `verified/`.

DNS и HTTP контейнеров периодически давали таймауты. Для итоговой сборки
сохранённые ответы дополнены отдельно маркированным импортом официальных страниц:
управление, география, CySAS и ECYSAP. Импорт не добавлен в обычный сетевой рецепт
как фиктивный успешный MCP-вызов. `official-supplement-expanded.json` содержит
нормализованные сведения и URL; `official-web-raw.txt` и `projects-web-raw.txt`
сохраняют ответ резервного web-reader. Основные корпоративные страницы повторно
разобраны из ранее полученного текста без изменения времени чтения.

```bash
docker exec -e PYTHONPATH=/app osint_proj-orchestrator-1 \
  python -u /app/tests/indra_pipeline.py replay-verified \
  --replay /reports/indra-comparison/final/evidence.json \
  --supplement /reports/indra-comparison/official-supplement-expanded.json
python3 tests/compare_indra.py --final replay-verified
```

Обычный сетевой `investigate` использует новые сборщики и рендереры, но внешний
web-reader автоматически из контейнера не вызывается. При повторении без
импорта результат зависит от доступности официального сайта. Точечная проверка
проектов по темам референса выполнена отдельно; восемь проектов с первой страницы
каталога получены обычным сборщиком.

Оставшиеся различия: полный исторический реестр полномочий не восстановлен;
выборка BORME содержит 10 актов и 43 события. Покрытие старых доменов `indra.es`,
архивных сертификатов/IP и отдельных региональных адресов меньше референса.
Текущая структура управления отличается от апрельского снимка; исторические
должности не выданы за действующие. Тематическое покрытие не измеряет полноту
или семантическую схожесть каждой строки.
