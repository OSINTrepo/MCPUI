# Экономия DRS без сокращения истории WHOIS

Система сохраняет весь успешный ответ истории домена: все нормализованные записи,
контактные имена, организации, даты снимков, регистрационные даты, сроки действия,
регистраторов, NS и статусы. Повторная сборка отчёта использует тот же набор записей.
История WHOIS не обрезается ни в MCP-клиенте, ни в кэше. Компактная выборка для LLM
не заменяет полные таблицы отчёта.

По [документации WhoisXML](https://whois-history.whoisxmlapi.com/api/documentation/making-requests),
`purchase` возвращает полный набор за **50 DRS-кредитов на домен**. `preview` стоит
**1 кредит**, но сообщает только количество записей. Равное количество не доказывает,
что сами записи не изменились, поэтому оно не используется как гарантия свежести.

## Поведение по умолчанию

- Первое обращение к новому домену получает полную историю и сохраняет её.
- Повторное обращение в течение **24 часов** возвращает все сохранённые записи без
  нового платного запроса истории. Это работает между отчётами, MCP-сессиями,
  серверами `whoisxml` и `directapi` и после пересоздания контейнеров.
- Одновременные обращения к одному домену объединяются файловой блокировкой.
  Она разделяет провайдера и API-аккаунт; другой ключ не получает чужой кэш.
- После истечения срока система снова получает полный набор. История без записей
  сохраняется максимум на час, чтобы быстрее замечать появление новых данных.
- Текущий WHOIS, DNS и остальные источники проверяются отдельно. Их данные не
  подменяются историей из кэша.
- Ошибки API, неполный ответ и неверный домен не сохраняются как успешная история.
  Просроченная история не выдаётся как свежая при отказе провайдера.
- В разделе WHOIS History показывается исходная дата получения ответа провайдера
  и отметка повторного использования. Дата сборки отчёта не обновляет эту дату.

Сохраняется полнота ранее полученной истории, но она может быть возрастом до суток.
Для проверки изменений прямо сейчас используйте принудительное обновление.

## Управление обновлением из UI

Обычная просьба «собери новый отчёт» использует правила кэша. Для новой покупки
добавьте к запросу: **«Принудительно обнови историю WHOIS»** или
**«Обнови историю WHOIS без кэша»**.

В MCP также доступны `investigate(task=..., refresh_history=True)` и
`whois_history(domain=..., force_refresh=True)`. У этих флагов явная стоимость:
повторная покупка полного набора. Одновременные обновления, начавшиеся до получения
одного нового ответа, используют результат этой покупки вместе.

## Настройки и хранение

В `.env` можно задать:

```dotenv
# Сутки по умолчанию; 3600 — час; 0 — отключить повторное использование.
WHOIS_HISTORY_CACHE_TTL_SECONDS=86400
```

После изменения `.env` пересоздайте серверы:

```bash
docker compose -f docker-compose.yml -f docker-compose.mcp.yml up -d --no-deps whoisxml directapi
```

Оба сервиса монтируют `./data/whois-history-cache` в `/cache/whois-history`.
Настройки находятся в `registry/servers.yaml`; генерируемый compose вручную
редактировать не нужно. Кэш не находится в каталоге публичных отчётов и исключён
из Git. API-ключи не записываются в файлы: используется их SHA-256-отпечаток.
Каталоги имеют права `0700`, файлы — `0600`; ответы сохраняются атомарно.

Для локального запуска без Docker можно задать `WHOIS_HISTORY_CACHE_DIR` в доступный
для записи приватный каталог. Если хранилище недоступно, инструмент выполняет обычный
запрос и сообщает, что результат не сохранён; экономия между сессиями тогда не действует.

## Импорт ранее оплаченных ответов

Можно заполнить кэш из сохранённого списка ответов WHOIS или `evidence.json`:

```bash
docker compose -f docker-compose.yml -f docker-compose.mcp.yml run --rm --no-deps \
  -v "$PWD:/workspace:ro" -v "$PWD/reports:/saved-reports:ro" \
  --entrypoint python whoisxml /workspace/scripts/seed_whois_history_cache.py \
  /saved-reports/example/whois-history.json
```

Импорт не делает сетевых запросов и сохраняет исходное `retrieved_at` или
`cache.fetched_at`. Без исходной даты, при истёкшем сроке или отсутствующем ключе
ответ пропускается. Старый ответ не затирает более свежий кэш.

## Пример стоимости

Для исследования двух доменов первый полный сбор истории стоит **100 DRS-кредитов**.
Ещё девять сборок в течение срока кэша стоят **0 дополнительных DRS-кредитов за
историю**, вместо 900 при девяти повторных покупках. У всех десяти отчётов остаётся
тот же полный набор записей. Это экономия 90% на этих десяти сборках;
первый сбор нового домена и принудительные обновления сохраняют стоимость провайдера.
Квоты других источников и стоимость LLM учитываются отдельно.
