# Пользовательские сценарии: что можно спрашивать у системы

Что аналитик реально пишет в чат — и что система с этим делает. Таблицы ниже
получены прогоном формулировок через оркестратор
(`scripts/`-скрипт прогона — см. «Как перепроверить» внизу), а не написаны «на
глаз».

Формулировать можно свободно: система сама определяет тип цели по тексту.
Ключевые слова («домен», «username», «ИНН») **не обязательны** — но с ними
надёжнее.

## Что система понимает

| Тип цели | Так спрашивают | Куда уходит |
|---|---|---|
| **username / ник** | «проверь username durov», «проверь durov», «@durov», «кто такой durov», «найди аккаунты durov в соцсетях», «ник pavel_durov» | Maigret, OpenOSINT |
| **email** | «проверь email test@example.com», «что известно про john@gmail.com», «пробей почту admin@company.ru» | OpenOSINT, Maigret |
| **домен / сайт** | «проверь домен github.com», «собери досье на сайт example.com», «что за сайт vk.com» | Shodan, VirusTotal |
| **IP** | «проверь ip 8.8.8.8», «что за адрес 1.1.1.1», «какие порты открыты на 8.8.8.8» | Shodan, VirusTotal |
| **URL** | «проверь https://example.com/page», «проверь ссылку на фишинг http://…» | VirusTotal |
| **хеш файла** | «проверь хеш 44d88612…», «это вирус? 44d88612…» (MD5/SHA1/SHA256) | VirusTotal |
| **компания по ИНН** | «проверь компанию по ИНН 7707083893» | Checko (карточка по ИНН) |
| **компания по названию** | «проверь компанию Сбербанк», «что известно о ООО Ромашка» | Checko (поиск по названию) |
| **тикер** | «проверь тикер AAPL», «$AAPL» | StockScope, The Stall (качество эмитента) |
| **криптокошелёк** | «проверь кошелёк <адрес>» | TWZRD (Solana) |
| **свободный запрос** | «что известно про телеграм», «помоги с расследованием» | DataNexus, BGPT |

**Составные цели работают:** «проверь домен github.com и ip 8.8.8.8» → обе цели;
«досье: username durov, email test@example.com» → обе. Несколько IP подряд — тоже.

**Язык:** русский и английский («check domain github.com» распознаётся так же).

## Что НЕ поддерживается (и честно об этом говорит)

Под эти цели в подключённом наборе **нет ни одного сервера**, поэтому система
отвечает «не поддерживается», а не делает вид, что проверила:

| Запрос | Ответ |
|---|---|
| «проверь ФИО Иванов Иван Иванович» | Не поддерживается: поиск по ФИО |

Это сознательное решение: общий веб-поиск вернул бы правдоподобный, но бесполезный
отчёт — и создал бы ложное впечатление проверки.

**Криптокошельки поддерживаются** (TWZRD — Solana; The Stall — EVM/санкции).
BTC-адреса покрыты слабо (TWZRD только Solana, The Stall платный).

## Скорость и охват

Оркестратор в авто-режиме опрашивает **2–3 быстрых и надёжных источника** на тип
цели — так запрос отрабатывает за **~5–10 с** (домен, IP, компания, тикер, хеш,
телефон). **username/email медленнее (~50–75 с)**: Maigret делает глубокий скан по
сотням соцсетей — это его природа, ускорить нельзя.

Остальные ~15 подключённых серверов (dnstwist, crawlgraph, voidly, brightdata,
zoomeye, vulneramcp, the-stall и т.д.) **доступны вручную** — выберите нужный в
панели MCP у сервера. Их не гоняют автоматически, чтобы не замедлять и не
переполнять память стенда.

> Битые/платные/за лимитом источники деградируют изящно — «источник недоступен:
> <причина>». Данные не выдумываются. `vulneramcp` (если подключить вручную) —
> только пассивная разведка, активные сканы не запускаются.

**Телефон поддерживается** (ContrastAPI): «проверь телефон +79001234567» →
страна, оператор, тип номера, таймзона. Владелец номера по открытым источникам
не определяется.

## Мета-вопросы

«что ты умеешь?», «какие источники подключены?», «what can you do» → система
отдаёт **каталог источников** по категориям, а не запускает веб-поиск.

Хотите увидеть план до запуска — спросите «какие источники будешь использовать
для github.com» (инструмент `plan`, ничего не выполняет).

## Отказы (этика)

Явно вредоносные запросы отклоняются **на уровне оркестратора**, а не только
системным промптом (промпт можно обойти или сменить модель — гейт срабатывает
всегда):

- «как взломать аккаунт X», подбор пароля, брутфорс
- «найди домашний адрес X», «где живёт X», паспортные данные, номер карты, СНИЛС
- «следить за X», слежка/stalking

Законный OSINT по открытым источникам не блокируется.

## Границы, о которых стоит знать

- **Пустой результат — это результат.** Если источник ничего не нашёл или
  недоступен (нет ключа, лимит, WAF), в отчёте будет «источник недоступен».
  Система не выдумывает данные.
- **Мусорный ввод** («asdkjhasdkjh») трактуется как username — для OSINT это
  разумная догадка, но результат будет пустым.
- **Статус ключа виден прямо в списке серверов** (панель MCP), в описании под
  именем:
  - 🔑 **НУЖЕН КЛЮЧ** — без ключа не работает (Shodan, VirusTotal, ZoomEye,
    Checko, Bright Data);
  - 🟡 **работает без ключа, ключ поднимает лимиты** (CrawlGraph);
  - 💳 **платный, оплата на стороне сервиса** (The Stall — x402/Stripe);
  - 🟢 **без ключа** — работает сразу (остальные).
  Ключ вводится тут же: ⚙/⚡ у сервера в панели MCP → поле + бейдж Set/Unset.
- **Ссылки на отчёт** всегда `http://localhost:8899/…`. Полный список реально
  созданных отчётов — http://localhost:8899/ (см. README → «Отчёты»).

## Как перепроверить

Матрица сценариев прогоняется скриптом внутри контейнера оркестратора:

```bash
docker cp user_scenarios.py osint_mcp_ui-orchestrator-1:/tmp/
docker exec osint_mcp_ui-orchestrator-1 python3 /tmp/user_scenarios.py a   # разбор формулировок
docker exec osint_mcp_ui-orchestrator-1 python3 /tmp/user_scenarios.py b   # сквозной прогон
```
