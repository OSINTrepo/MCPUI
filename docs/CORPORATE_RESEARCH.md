# Поиск юридических лиц по сайтам и архивам

Расширенный этап встроен в `investigate`: он работает и при запросе из UI.
Пример: «Исследуй example.trade и example-russia.trade: найди юридические лица,
ИНН, архивные договоры и контакты, проверь историю, финансы и связи».

## Что собирает система

1. Использует уже прочитанные корпоративные страницы либо получает главную
   страницу через Bright Data. Для недоступного сайта ищет снимки Wayback;
   при явном запросе истории проверяет архив и для работающего сайта.
2. Читает до пяти ссылок на контакты, договоры, раскрытие информации и реквизиты
   на домен. Архивные PDF загружает с ограничением размера и извлекает текст.
   Дата реально возвращённого снимка отделена от даты запроса и даты чтения.
3. Извлекает названия компаний с проверяемой цитатой и ищет связанные публикации.
   LLM предлагает имена; код отклоняет название, которого нет в указанной цитате.
   При отказе LLM остаются поиск названий ООО/АО в кавычках и явных ИНН.
4. Проверяет российские юрлица через Checko: контрольную цифру ИНН, точное имя,
   уникальность результата и совпадение ИНН в каждом последующем ответе.
   При нескольких одноимённых компаниях не выбирает первую автоматически.
5. Получает карточку, участников, руководство, ОКВЭД, финансовые формы, историю,
   арбитражные дела, Федресурс и ЕФРСБ. При настроенном NewDB выполняет ограниченную
   проверку ЕГРЮЛ; источник может расходовать свой баланс.
6. Формирует отдельный раздел для каждого проверенного ИНН. Разные юридические
   лица не подменяют исходную компанию и не сливаются в единую финансовую группу.
   Допускается один дополнительный переход по связанному ОГРН из карточки
   руководителя; повторного неограниченного обхода по ФИО нет.

Прочитанные страницы, снимки, методы, время получения, контрольные суммы текста
и ответы инструментов сохраняются в структурированном результате этапа.
Ссылка на источник сопровождает кандидата и реестровое досье.
Полные материалы доступны в отдельном `.research.json` рядом с HTML/PDF.
Публичные веб-ответы кэшируются на семь дней в `/reports/.corporate-cache`:
исторические снимки используются повторно, живые страницы и поиск — только
как резерв при сбое. В отчёте сохраняется исходная дата и отметка повторного
использования. Реестровые карточки не подменяются этим кэшем.

## Как интерпретировать результат

- «Название встречается в документе» не означает «владеет доменом».
- Архивный email одного исследуемого домена на другом — контактная связь.
  Совпадение серверного IP само по себе не устанавливает общего владельца.
- Имена Fund, Ltd. и LLP не объединяются. Иностранный регистрационный номер
  в составе учредителей не превращается в российский ИНН.
- Связи людей сопоставляются по идентификатору реестра, а не по одному ФИО.
  Гражданство и конечный бенефициар по имени не определяются.
- Пустая финансовая строка остаётся неизвестной. Отрицательный капитал не
  скрывается. Сумма иска не обозначается как непогашенный долг.
- Отсутствие записей в ответе, ошибка источника и окончание бюджета — разные
  результаты. Необследованные страницы и реестры не считаются «чистыми».

## Настройка и обновление

```dotenv
ORCHESTRATOR_CORPORATE_RESEARCH=1
ORCHESTRATOR_RESEARCH_DEADLINE=240
ORCHESTRATOR_RESEARCH_CALLS=64
```

Это дополнительный бюджет после основного сбора. Лимит запросов относится к
основным MCP-вызовам этапа; у CDX/PDF и NewDB отдельные ограничения внутри того
же временного бюджета. По умолчанию исследуются до
двух доменов, шести российских юрлиц и двух поисковых запросов по выявленным
брендам. MCP-вызовы выполняются с ограниченной конкурентностью; UI получает
уведомления о прогрессе. При окончании бюджета отчёт сохраняет полученную часть.
Время всего отчёта включает также основной сбор и LLM-синтез.

```bash
python3 generator/generate.py
docker compose -f docker-compose.yml -f docker-compose.mcp.yml build orchestrator
docker compose -f docker-compose.yml -f docker-compose.mcp.yml up -d --no-deps orchestrator
```

Реестр `registry/servers.yaml` задаёт переменные контейнера; сгенерированные
compose/catalog/librechat файлы вручную не редактируются. Для отключения нового
этапа установите `ORCHESTRATOR_CORPORATE_RESEARCH=0` и пересоздайте orchestrator.

## Проверки и ограничения

`tests/unit_corporate_research.py` проверяет атрибуцию, лимиты, отказы источников,
извлечение имён, ИНН, архивные даты, контакты и расширенную финансовую форму.
Зависимости установлены в контейнере orchestrator.

Архив может быть неполным; изображение сертификата требует отдельного чтения и
проверки подлинности, OCR автоматически не выполняется. PDF ограничен 8 МБ,
35 страницами и 60 000 символами извлечения. Текстовый слой сканированного PDF
может отсутствовать. Доступ к зарубежным реестрам, ФССП, полным судебным актам,
истории регистрации доменов и закрытым данным зависит от отдельных источников.
Расширение не обещает получить все существующие сведения о компании.
