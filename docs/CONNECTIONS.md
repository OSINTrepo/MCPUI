# Исправление соединений — 2026-09-10

## Исправления приложения

- Supergateway больше не падает из-за отклонённого Promise при позднем ответе
  после отключения HTTP-клиента. Неудачная инициализация закрывает транспорт;
  отмена обычного запроса не уничтожает остальные запросы активной сессии.
  Идемпотентный патч применяется при старте всех stdio-контейнеров, включая
  ранее собранные образы; Compose монтирует файл из servers/base.
- MCPClient сообщает HTTP-код и некорректный ответ initialize/tools/list как
  ошибку, а не пустой каталог. Закрытие выделенной сессии выполняется и при
  неуспешной инициализации. Диагностические исключения не содержат URL/ключей.
- Checko, OpenOSINT, ZoomEye запускают uvx с --offline. Зависимости уже входят
  в образы; старт каждой команды проверен в новом контейнере с --network none.
  Доступ к API самих инструментов по-прежнему требует сети. Обновление пакетов
  выполняется при сборке образов, не при каждой новой MCP-сессии.
- Реестр DomScan исправлен: требуется API key (X-API-Key), UI показывает поле
  DOMSCAN_API_KEY. Без авторизации endpoint возвращает HTTP 401. Ключ в .env
  отсутствует; успешная авторизация не заявлена. Официальное описание:
  https://domscan.net/mcp-domain-checker

## Сеть хоста

В ходе диагностики DNS не отвечал и на Ubuntu-хосте, и в Docker. Stub 127.0.0.53
использовал шлюз 192.168.40.2; прямые запросы к публичным DNS также зависали.
Позднее запросы api.brightdata.com и api.deepseek.com стали успешны, включая
прямые запросы к шлюзу и 1.1.1.1. DNS-настройки в ходе исправления не менялись;
причина восстановления внешней сети не установлена.

Ранее HTTPS к dns.google и cloudflare-dns.com с закреплённым IP возвращал
сертификат от Kaspersky Anti-Virus Personal Root Certificate; проверка цепочки
завершалась ошибкой 19. Это подтверждает проблему доверия для этих соединений,
но не доказывает причину всех DNS-таймаутов. CA не добавлялся, TLS-проверка
не отключалась. Настройки Windows/гипервизора недоступны из репозитория.
